# 시간 모형 검토 (2026-10, 진행 중)

속성·종합 티어가 옛 시즌을 다루는 방법(반감기 둘)을 검토한 기록이다. **코드와 인자는 아직 그대로다.** 다음 세션에서
아래 "정할 것"부터 이어 간다. 숫자는 시즌 1–41(체급 비례 분배) 기준이고, 재현 스크립트는 [`time-review/`](time-review/)에 있다.

## 1. 문제: 시즌마다 S·SS 인데 속성 티어는 A

미하라 : 본딩 체인의 작열 시즌은 1.66 SS · 1.34 S · 1.17 S · 1.11 S · 1.42 SS 인데 작열 티어는 **0.99 A** 다.
드문 일이 아니다. 지금 시점, 자기 속성 칸 중 시즌 2개 이상이고 B 이상을 찍은 81칸에서

- 41칸은 추정치가 관측된 모든 시즌 값보다 낮다.
- 18칸은 속성 티어가 그 칸의 모든 시즌 티어보다 낮다. 크라운 철갑(1.54–1.84, 전부 SS) → S 1.21,
  라피 : 레드 후드 작열(전부 SS) → S 1.30 등.

## 2. 지금 모형의 구조

```
칸 = Σ 믿음ᵢ · 기여도ᵢ · 환산ᵢ / Σ 믿음ᵢ
믿음ᵢ = 0.5^(시즌 i → 지금 / 180일)          (half_life_days)
환산ᵢ = 0.5^(시즌 i → 같은 약점의 가장 최근 시즌 / 300일)   (value_half_life_days)
```

- 한 칸 안에서 믿음의 "지금부터"는 모든 시즌에 같은 상수배가 붙어 약분된다. 실제로는 "같은 약점의 가장 최근
  시즌부터의 거리"다. 두 반감기가 **같은 변수**에 걸린 인자 둘이다.
- 그래서 칸 = **[112.5일 반감기 평균] × [Σ0.5^(g/112.5) / Σ0.5^(g/180)]** 로 갈린다. 미하라: 1.32(S) × 0.75 = 0.99.
- 뒤 계수(깎기)는 기여도를 보지 않는다. 옛 시즌이 몇 개 있고 얼마나 떨어져 있는지만 본다. 같은 약점 시즌이 넷 이상이면
  실제로 떨어졌든 아니든 약 0.7–0.8 이 곱해진다.
- 파워 인플레(체급)는 티어에 안 들어간다(CLAUDE.md). 체급은 덱 몫 나누기에만 쓰이고 시간 가중이 없다. 티어 안의
  시간 개념은 위 둘(그리고 `fill_from_later` 가 180일을 앞으로 뒤집어 쓰는 것)뿐이다.

## 3. 측정

**기여도가 줄어드는 속도는 자기 속성 칸과 다른 속성 칸이 다르다.** 같은 니케·같은 약점의 앞뒤 시즌 쌍(앞 시즌 0.3 이상)에서
절반이 되는 데 걸리는 날:

| 시즌 ~까지로 재면 | 20 | 25 | 30 | 35 | 41 |
|---|---|---|---|---|---|
| 자기 속성 칸 | 404 | 422 | 492 | 496 | 521 |
| 다른 속성 칸 | 290 | 285 | 271 | 279 | 290 |

앞 시즌 1.0 이상인 자기 속성 칸은 약 600일. 300일은 종합(다섯 칸 중 넷이 다른 속성)으로 맞춘 값이라 속성 티어를 너무
세게 깎는다. 자기 속성 쪽이 점점 길어지는 건 메타가 약점을 더 따르게 된 흐름과 맞는다.

**"옛 기록을 지워도 비슷한 티어"가 지켜지나.** 2024-06 이후 각 시즌 시작 시점, 그때까지 0.3 이상 찍은 칸
(자기 403건, 다른 938건). 평균차가 음수면 옛 기록이 값을 끌어내린다는 뜻:

| 방식 (믿음 / 환산) | 1년 넘은 시즌 지우면: 평균차 · 니케마다 차이 · 티어 바뀜 (자기 칸) | 같은 것 (다른 칸) | 다음 시즌 예측 오차 (자기 / 다른) |
|---|---|---|---|
| 현재 180 / 300 | −0.036 · 0.061 · 28% | +0.007 · 0.046 · 27% | 0.185 / 0.205 |
| 가) 90 / 자기 500·다른 230 | −0.002 · 0.018 · 12% | −0.003 · 0.018 · 9% | 0.191 / 0.191 |
| 90 / 잰 값(520·290) | −0.001 · 0.018 · 12% | +0.001 · 0.019 · 12% | 0.192 / 0.197 |
| 믿음 없음 / 500·230 | −0.015 · 0.110 · 52% | −0.013 · 0.085 · 45% | 0.218 / 0.206 |
| 가장 최근 시즌 하나 | 0 · 0 · 0% | 0 · 0 · 0% | 0.191 / 0.197 |
| 반감기 하나 90, 환산 없음 | +0.023 · 0.028 · 11% | +0.031 · 0.037 · 23% | 0.219 / 0.233 |

- 종합은 평균으로 지켜지지만(300일을 고른 기준) 속성 티어는 옛 기록이 끌어내린다.
- 새 시즌이 들어올 때 티어가 바뀌는 비율은 현재 · 가) · 최근 1시즌 모두 약 50% 로 같다. 지금의 평균 내기가 안정성을 사 주지 않는다.
- 다음 시즌을 높게 잡는 정도(자기 칸)는 현재가 가장 작다(+0.08, 가)는 +0.12). 깎기가 다음 시즌까지의 하락을 미리 반영하기
  때문이다. 티어가 재는 것은 **"지금까지 보여 준 값"으로 정했다**(사용자 결정). 다음 시즌 예상과는 같은 약점이 돌아오는
  약 5개월 동안의 하락(자기 ×0.8, 다른 ×0.65)과 평균 회귀만큼 다르다.

## 4. 안 가) — 반감 속도를 재서 쓰기

- 믿음 반감기 **90일** (설정에 남는 판단값 하나 — 빼면 위 표처럼 크게 나빠진다).
- 환산은 자기·다른 칸 따로, 속도는 설정값이 아니라 **데이터에서 잰다**(위 쌍 방법, 그 시점까지의 데이터로).
  `value_half_life_days` 는 없앤다. 잰 값(520·290)과 고른 값(500·230)의 결과가 같다.
- 지금 시점에 미하라 S 1.22, 크라운 SS 1.45, 레드 후드 작열 SS 1.60. 속성 티어 197칸 중 28칸이 바뀌고 대부분 오른다.
- 할 일: `tiers.py`, `model.js`(테스트가 같은지 봄), `config/tiers.yaml`, 종합 컷 다시 맞춤(같은 규칙), metrics.md 3절,
  power.md · 파워 인플레 탭에 "기여도 반감"을 판의 세기 옆에 나란히.

사용자 의견: 500·230·90 셋이 있고 인플레가 따로인 게 불편하다 → 속도를 재는 값으로 바꿔 설정은 하나로. 그다음 아래 5절의
재구성 검토가 나와서, 가)는 5절 결과를 보고 다시 정하기로 했다.

## 5. 체급 관점의 재구성 검토

### 사용자 가설과 검증

| 주장 | 판정 | 근거 |
|---|---|---|
| 1. 체급은 출시 때 정해지고 안 변한다 | 대체로 맞음 | 출시 뒤 경과별 덱 대미지 예측 빗나감 ±0.01, 추세 없음(power.md). 단 칸이 넷(자기/다른 속성 × 애장품 전/뒤), 보스 기믹은 평균에 묻힘, 가정을 사후 확인한 것 |
| 2. 새 니케 체급은 서서히 오른다 | 평균으로 맞음 | 출시 1년당 자기 ×1.149 · 다른 ×1.117, 그러나 R² 0.40, 추세 주변 흩어짐 ±16–21% > 1년 치 12% |
| 3. 체급 높은 순으로 25명, 낮을수록 채용 감소 | 방향은 맞음, "반드시"는 아님 | 체급 순위 1–5위 사용률 86%, 6–15위 75%, 16–25위 56–61%, 26–30위 43%, 31–40위 25%, 41–60위 8%. 절반 이상이 쓰는 니케의 28% 는 체급 25위 밖. 순위로 사용률 R² 0.55. 버스트 안에서만 줄 세워도 순위상관 0.69 그대로 |
| 4. 쓰이면 대미지는 체급으로 정해진다 | 모형으로 맞음 | 같은 사람 다섯 덱의 로그 덱 대미지 R² 0.90(남는 오차 ±13%). 곱/합 미정, 교체 실험 0.74배, 자기 딜 아님 |
| 5. 기여도 = 채용 × 쓰였을 때 몫 | 맞음, 채용이 대부분 | log 기여도 분산 1.08 = 채용 0.68 + 몫 0.13 + 공분산 0.26 |
| 6. 근본은 체급인데 직접 못 얻는다 | 맞음 | 같은 랭킹에서 추정한 숨은 값. 안 쓰인 니케(30명)·늘 같이 쓰인 짝은 못 잼 |
| 7. 수명 = 25인에서 빠짐, 인플레 = 판 전체가 세짐 | 맞음, 데이터가 가장 강하게 받침 | 아래 |

**채용은 "체급 − 그 시즌 25번째 체급"의 S자 곡선이고, 시기와 무관하게 같다:**

| 25번째와의 log 체급 차 | ≤ −0.2 | −0.1–0 | 0–+0.1 | +0.1–+0.3 |
|---|---|---|---|---|
| 사용률 (시즌 16–28 / 29–41) | 1% / 2% | 20% / 24% | 65% / 65% | ~80% / 70–76% |

**기여도가 주는 건 날짜가 아니라 판과의 거리 때문이다.** 앞뒤 시즌 쌍의 log 기여도 변화를 설명하는 정도(R², 자기 / 다른):
날짜 0.01 / 0.08 · 판의 세기 변화 0.03 / 0.09 · 날짜 + 날짜×(체급 − 판) 0.14 / 0.20 · 판의 세기 변화 + ×(체급 − 판)
0.17 / 0.21. 1년 뒤 남는 비율 추정(자기 칸): 크라운 ×0.92, 미하라 ×0.65, 리타 ×0.46, 모더니아 ×0.31,
레드 후드 ×1.53(늘어남 — 상한 필요). 판의 세기를 시계로만 쓰는 건 날짜와 같다(상관 0.8).

(이 절의 체급은 전 시즌으로 푼 값이라 누수가 있다. 실제로 쓰려면 시점마다 그때까지로 다시 푼다.)

### 재구성 방향 (아직 설계 전)

- 체급이 고정이면 **옛 시즌은 낡은 데이터가 아니다** — 체급을 재는 데 최근 시즌과 똑같이 유효하다. 낡는 건 커트라인
  (그 시즌 25번째 체급, 곧 인플레)뿐이다. 반감기 없이 "체급(전 기간) − 지금의 커트라인"으로 지금의 가치를 낼 수 있고,
  옛 기록을 지우면 체급 추정이 덜 정밀해질 뿐 한쪽으로 쏠리지 않는다.
- 수명 ≈ (체급 − 커트라인) ÷ 인플레 속도로 예측 가능해진다.
- 걸리는 점:
  - 채용을 체급으로 설명하는 정도가 절반(R² 0.52–0.55). 체급만으로 티어를 만들면 관측 기여도와 어긋난다 → 관측
    기여도는 두고 **시간 환산만** 체급 − 커트라인으로 하는 절충이 현실적.
  - CLAUDE.md 규칙 "체급은 덱 몫 나누기 한 곳에만", "인플레는 티어에 넣지 않는다"를 바꿔야 한다(사용자 결정).
  - 시점마다 그때까지로 다시 풀기(누수), 못 재는 니케·짝 처리, 브라우저(`model.js`)로의 이식(미리 계산해 `decks.json`
    처럼 넘기기).
